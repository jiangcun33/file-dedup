# Windows 文件去重软件 — 技术方案设计

> 版本：v1.0（初稿）
> 依据：`research\文件去重软件调研报告.md`（18 个开源项目调研结论）
> 需求确认：Windows GUI 桌面应用 / Rust 技术栈 / 精确去重+文件名模糊+相似图片+相似视频+音乐去重+附加清理 / 操作：回收站、永久删除、硬链接替换、移动复制

---

## 1. 项目概述

一款面向 Windows 的**安全优先**的文件去重桌面应用。用户选择目录后，软件只读扫描，找出重复文件（精确内容重复、文件名相似、图片/视频/音乐相似），按组展示结果并给出可释放空间，用户确认后执行删除/硬链接替换/移动等操作。

**对标项目**：Czkawka（功能全面）、dupeGuru（模糊匹配）、MangoDisk（安全设计）、fclones（性能算法）。

## 2. 需求范围（已确认）

### 2.1 核心功能
| 编号 | 功能 | 优先级 | 说明 |
|---|---|---|---|
| F1 | 精确内容去重 | P0（MVP） | 三级漏斗：大小→部分哈希→全文件哈希 |
| F2 | 哈希缓存 | P0 | SQLite 缓存，二次扫描提速 |
| F3 | 扫描过滤 | P0 | 扩展名、大小范围、修改时间、路径正则、排除目录 |
| F4 | 保留策略 | P0 | 按修改时间/文件名/路径深度决定每组"原件" |
| F5 | 结果展示 | P0 | 分组列表、可排序/过滤/多选、可释放空间统计、预览 |
| F6 | 处理操作 | P0 | 回收站、永久删除、硬链接替换、移动/复制到目录 |
| F7 | 文件名模糊匹配 | P1 | dupeGuru 式词相似度阈值匹配 |
| F8 | 相似图片查找 | P1 | 感知哈希（pHash/DCT），容忍缩放/压缩/水印 |
| F9 | 音乐去重 | P1 | 标签比较（ID3/FLAC 等）；音频指纹放 P2 |
| F10 | 附加清理工具 | P1 | 空文件夹、大文件、临时文件查找 |
| F11 | 相似视频查找 | P2 | FFmpeg 抽帧 + 帧 DCT 哈希序列匹配 |
| F12 | CSV/JSON 导出 | P2 | 结果导出便于外部处理 |

### 2.2 安全机制（贯穿所有操作）
- 扫描过程**只读**，不做任何文件系统修改（MangoDisk 设计原则）
- 每组重复**自动保留至少一份**（参考文件不可被标记删除）
- 参考文件夹保护：指定目录中的文件永远只当"参考"，不可删除
- 执行前二次确认 + 操作前 TOCTTOU 校验（文件被改动则中止该组操作）
- 双重遍历保护（同一目录/符号链接环检测）
- 回收站为默认操作，永久删除需额外确认
- 操作日志记录（时间、路径、操作类型、结果）

## 3. 总体架构

采用 Czkawka 验证过的**三层分离**架构，核心引擎与 UI 完全解耦：

```
┌─────────────────────────────────────────────┐
│  GUI 前端（Tauri 2 + Vue3 / 或 Slint）        │
│  目录选择 · 进度 · 结果表格 · 预览 · 设置      │
└──────────────────┬──────────────────────────┘
                   │ Tauri Command / 事件        （或 Slint 回调）
┌──────────────────▼──────────────────────────┐
│  dedup-core（Rust 核心库，无 UI 依赖）        │
│  ┌──────────┬──────────┬──────────────────┐  │
│  │ scan     │ hash     │ match            │  │
│  │ 目录遍历  │ 三级漏斗  │ 分组/相似算法     │  │
│  ├──────────┼──────────┼──────────────────┤  │
│  │ tools    │ cache    │ action           │  │
│  │ 附加工具  │ SQLite   │ 回收站/删除/链接  │  │
│  └──────────┴──────────┴──────────────────┘  │
└──────────────────┬──────────────────────────┘
                   │
┌──────────────────▼──────────────────────────┐
│  Windows 平台层                               │
│  IFileOperation(回收站) · NTFS 硬链接 ·        │
│  Unicode/长路径 · FFmpeg(视频) · 文件属性      │
└─────────────────────────────────────────────┘
```

- **dedup-core**：纯 Rust 库，扫描/匹配/操作全部逻辑，可用 `cargo test` 独立测试，将来可复用于 CLI
- **GUI**：Tauri 2（Web 前端，表格/树形组件生态成熟）或 Slint（纯 Rust，无 Web 依赖），见 §4 选型
- **可选 dedup-cli**：调试与自动化（P2 之后再考虑）

## 4. 技术选型

### 4.1 GUI 框架（Rust）
| 框架 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **Tauri 2** | 前端生态成熟（表格/树/多选组件现成）；MangoDisk 同款；UI 开发效率高；包小 | 依赖 WebView2（Win10/11 自带）；需 Node.js 工具链；前后端语言分离 | **首选（推荐）** |
| Slint | 纯 Rust；Czkawka(Krokiet) 同款；性能好 | 复杂表格（排序/多选/虚拟滚动）需大量自研；GPL 或商业许可 | 备选（若想纯 Rust） |
| egui | 开发快，原型友好 | 大数据量表格性能一般 | 不推荐做主 UI |

> 推荐 **Tauri 2 + Vue 3 + Element Plus**（表格 el-table 支持排序/多选/虚拟滚动，开箱即用）。

### 4.2 核心依赖
| 用途 | 选型 | 理由 |
|---|---|---|
| 快速哈希 | `xxhash-rust`（xxh3-128） | fclones/fifi 同款，极快，适合部分哈希阶段 |
| 确认哈希 | `blake3` | czkawka 同款，多线程、快且安全 |
| 并行 | `rayon` | Rust 事实标准 |
| 进度/取消 | `crossbeam-channel` + `AtomicBool` | czkawka 同款模式 |
| 缓存数据库 | `rusqlite`(bundled) | fdupes -c / dude 同思路，稳定、无外部依赖 |
| 图片解码+感知哈希 | `image` + `img_hash`（或自研 DCT 哈希） | pHash/dHash；cbird 的多算法思路留作扩展 |
| 音乐标签 | `lofty` | 读写 ID3/FLAC/MP4 等标签 |
| 音频指纹(P2) | `rusty-chromaprint` | czkawka 同款，AcoustID 算法 |
| 视频(P2) | `ffmpeg-next`（或 ffmpeg CLI 子进程） | 抽帧解码；静态链接方案待评估 |
| 回收站 | `trash` crate | 跨平台封装 Windows IFileOperation |
| 硬链接 | `std::fs::hard_link` | 内置 |
| 字符串相似 | `strsim` | Jaro-Winkler/Levenshtein，配合自研词相似度 |
| 正则/glob | `regex` + `globset` | 路径过滤 |

### 4.3 语言版本与工具链
- Rust edition 2021+（cargo workspace）
- Windows 10/11 x64 目标；NSIS 安装包（Tauri bundler 内置）+ 便携版

## 6. 核心算法设计

### 6.1 精确去重（三级漏斗，F1）
```
阶段1 按大小分组      遍历时记录 size → HashMap<size, Vec<FileEntry>>，唯一 size 直接淘汰
阶段2 部分哈希        ≥64KB 的文件读头 4KB + 尾 4KB，xxh3-128 混合 → 候选组
阶段3 全文件哈希      blake3 逐块读全文 → 相同哈希即重复（字节级确认）
                      → 可选"逐字节比对"二次确认（防极端哈希碰撞，默认开启）
```
- 并行：rayon 并行处理各候选组；读文件用大缓冲区（1MB）减少系统调用
- 内存：FileEntry 用路径前缀压缩（fclones 思路）或 Arc<PathBuf>；大目录流式处理
- 缓存：`cache/scan_cache` 表（path, size, mtime, partial_hash, full_hash），mtime+size 变化才重算

### 6.2 文件名模糊匹配（F7，dupeGuru 算法）
- 把文件名按空白拆成词集合
- 相似度 = 相同词数×2 / 两文件总词数（每词计 2 分）
- 相似词（编辑距离 ≤1）可计入匹配（可选开关）
- 阈值可调（默认 80%），只对**同目录或相近目录**的文件先做大小粗筛再比较，避免 O(n²)
- 注意：模糊匹配结果默认标记为"需人工确认"，不参与自动保留策略

### 6.3 相似图片（F8，P1）
- 解码统一到 RGB 缩略图（如 32×32，`image` crate 缩略）
- 感知哈希：pHash（DCT 低频系数比较）为主，dHash 为辅
- 汉明距离阈值聚类（参考 dude 的 DBSCAN 思路；小规模可直接两两比较 + 阈值）
- 缓存感知哈希值（图片解码慢，必须缓存）
- 可选：旋转检测（90/180/270 重算哈希，dude 有该功能）

### 6.4 音乐去重（F9，P1 标签 / P2 音频指纹）
- **标签模式**：`lofty` 读取 artist/title/album/时长 → 字段相似度（复用 6.2 算法）→ 阈值匹配
- **内容模式(P2)**：`rusty-chromaprint` 生成音频指纹（先 FFmpeg 解码为 PCM 单声道 11025Hz）→ 指纹比对
- 同一首歌不同码率/格式（MP3 vs FLAC）由内容模式覆盖

### 6.5 相似视频（F11，P2）
- FFmpeg 解码抽帧：均匀采样（如每 5 秒一帧，视频缩略图尺寸）
- 每帧 DCT 哈希（复用 6.3）
- 序列匹配：滑动窗口 + 汉明距离阈值，容忍帧率/分辨率差异（czkawka 同思路）
- 成本高，仅对用户指定目录启用，默认关闭

### 6.6 附加清理工具（F10，P1）
| 工具 | 算法 |
|---|---|
| 空文件夹 | 后序遍历，子项全空即标记；可选忽略隐藏文件 |
| 大文件 | 遍历收集 → Top N（可配 N 与最小大小）|
| 临时文件 | 扩展名/路径特征匹配（*.tmp、%TEMP%、浏览器缓存路径规则，参考 Winapp2.ini 思路）|

## 7. 数据持久化

- **SQLite 单库**（`%APPDATA%\FileDedup\cache.db`）：
  - `scan_cache`：文件哈希缓存（path, size, mtime, partial_hash, full_hash, scanned_at）
  - `ignore_list`：用户忽略的匹配对
  - `settings`：KV 配置（阈值、过滤规则、保留策略）
  - `operation_log`：操作历史
- 缓存失效：mtime/size 变化即失效重算；支持"清理缓存"按钮
- 前端无状态，全部数据经 Tauri command 获取

## 8. Windows 平台集成

| 能力 | 实现 |
|---|---|
| 回收站 | `trash` crate → IFileOperation，返回是否成功；失败回退永久删除需确认 |
| 硬链接 | `std::fs::hard_link`；注意 NTFS 每文件 1023 链接上限（jdupes 文档提示）|
| Unicode/长路径 | 全链路 UTF-8；长路径启用 `\\?\` 前缀或 `std::os::windows::ffi` |
| 文件元数据 | `std::fs::metadata`：size/mtime/ctime；权限与只读属性处理 |
| 只读文件删除 | 先清只读属性再删（须确认）|
| 系统目录保护 | 默认排除 `C:\Windows`、Program Files 等（可配置）|
| 视频解码(P2) | ffmpeg 静态库（vcpkg 或 ffmpeg-sys-next 静态 feature）|

## 9. 性能设计

- 全阶段 rayon 并行；读 I/O 与哈希 CPU 任务流水化
- 三级漏斗避免对大文件全集哈希（关键：只哈希候选组）
- 路径前缀压缩控制内存（百万级文件场景）
- 进度报告：跨线程 channel 推送 (phase, done, total)，前端进度条；`AtomicBool` 取消，取消后保留已得部分结果
- 哈希缓存使重复扫描接近瞬时

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| 视频 FFmpeg 集成复杂度高 | 延后至 M4；先验证静态链接方案，失败则降级为 ffmpeg CLI 子进程 |
| 感知哈希误报/漏报 | 多算法组合 + 阈值可调 + 预览人工确认；参考 cbird 的多算法分层 |
| 回收站 API 平台差异 | 用 `trash` crate 抽象；失败回退逻辑明确 |
| 大目录内存占用 | 路径压缩、流式处理；扫描前预估并提示 |
| 硬链接误操作导致数据丢失 | 操作前 TOCTTOU 校验 + 每组保留参考 + 二次确认对话框 |
| 模糊匹配 O(n²) | 先按目录+大小粗筛，仅小集合做两两比较 |
| GUI 表格大数据卡顿 | Element Plus 虚拟滚动 + 前端分页加载 |
